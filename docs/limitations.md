# Limits and remaining work

- This models scheduling and arena policy, not a Voyager ISA, computer, OS, RTOS or physical embedded board. The host runs macOS. There are no interrupts, caches, peripherals, dependencies, jitter, energy measurements or real fault/recovery behaviour.
- Execution demand and deadlines are researcher-selected inputs. No hardware WCET was measured. Maximum observed response in a finite horizon is not a schedulability proof. Completion-yield jobs can block high-priority arrivals.
- The utilisation family uses a small harmonic period set, synchronous offsets, positive integer rounding and a family acceptance tolerance. Conditional retries restrict the workload distribution. Ten seeds describe these constructed families, not all embedded software. Six sensitivity cases cannot establish phase robustness; the low-load staggered case already changes deadline outcomes.
- Static maxima and bounded first-fit with 32 descriptors are the two policies tested. Five-owner traces and deliberately staggered or hole-forming lifetimes shape their results. Staggered workloads favour reuse, while declared 512-byte maxima can exceed sizes realised by some owners. There is no claim about all dynamic allocators, native malloc or TLSF.
- Metadata is outside the active payload budget and fully bounded. Small selected budgets do not reduce compiled arrays or whole-process RAM. Replay includes both arenas; Scheduler includes its own arena. Neither the guard nor reported sizeof values cover all host allocations.
- The new guard covers tested C++ allocation paths and includes aligned/array/nothrow forms. It does not intercept direct malloc or all library internals. Source and symbol audits complement it, rather than claiming a mathematical no-allocation proof.
- Compiler -fstack-usage estimates are per function at -O3. Whole-call-chain runtime stack high-water usage was not measured. All reported sizes are specific to the recorded Apple Clang arm64 ABI.
- Apple Clang 21 was used, not the intended research GCC compiler. Normal and ASan/UBSan tests passed. A future GCC validation is still useful; none is claimed. CMake's recorded flags field contains base/Release configuration flags; standard/warning/sanitizer options also come from CMakeLists.txt. The sanitizer build used Debug and explicit sanitizer options, not the normal batch binary.
- No optional preemptive comparator, application yield segmentation, native-heap illustration or nonzero overhead model was implemented. No host runtime is presented as target performance. Allocator operation counts do not affect task deadlines in this zero-overhead model.
- The original guide/reference library was not supplied beyond the build plan. Only the Liu–Layland primary paper was checked for the benchmark caveat. No guide bibliography, hardware history or flight reliability claim is treated as independently verified.
- Git milestone timestamps are assigned retrospectively from 17 August to 19 October 2026. Implementation and measurements were performed on 19 October. The Git dates do not establish a historical work schedule.

All required E1–E4 and specified sensitivity runs are present in `results/full`; no required experiment cell is outstanding. Future work: try the same saved inputs on GCC, then consider an explicitly labelled segmented-yield or preemptive extension if needed.
